# Garmin MS Health Dashboard

Interactive Streamlit dashboard for Garmin Forerunner 245 activities with automated alert monitoring and MS-specific health tracking.

## Features

- **Activity Metrics**
  - Weekly training load (distance, duration, calories) by sport.
  - Cardio efficiency (pace vs HR).
  - Pacing consistency (lap pace variance).
  - Heart rate drift analysis.
  - Gait stability and stride range.
  - Fatigue indicators (Ground Contact Time drift).
  
- **Automated Alerts**
  - MS-specific flags: gait drift, HR drift, heat sensitivity.
  - Configurable thresholds (automated baseline calculation).
  - Slack/Email notifications for triggered alerts.
  
- **Alert History & Management**
  - Table view of alerts from `alert_logs` SQLite table.
  - **Acknowledge button** for each alert (updates `acknowledged`, `ack_by`, `ack_time`).
  - Interactive filtering by metric and date range.
  - Visualizations:
    - Alert counts by metric.
    - Daily alert counts over time.
    
- **Logging**
  - Full persistence in `alert_logs` table.
  - Tracks acknowledged alerts with user and timestamp.

## Requirements

- Python 3.9+
- SQLite
- Streamlit
- Pandas
- Matplotlib
- Slack SDK or smtplib for email alerts (optional)

See `requirements.txt` for full package list.

## alerts module

The **alerts.py** module is a health metrics monitoring and alerting system for Garmin fitness data. Here's what it does:

## Core Functionality

**1. Health Metric Monitoring**
- Monitors 4 key health indicators from your Garmin activities:
  - **Gait Stride Range**: Detects deviations in stride pattern stability
  - **Heart Rate Drift**: Identifies abnormal HR increases during activities (late vs early)
  - **GCT Drift**: Tracks Ground Contact Time changes (fatigue indicator)
  - **Heat Sensitivity**: Analyzes correlation between temperature and HR drift

**2. Statistical Baseline Detection**
- Computes baselines using either:
  - Median & MAD (Median Absolute Deviation) for larger datasets (≥8 samples)
  - Mean & Standard Deviation for smaller datasets
- Uses z-score calculations to detect when metrics breach thresholds (default: 2.0 standard deviations)

**3. Smart Alert System**
- **Cooldown mechanism**: Prevents alert spam (default 24-hour cooldown per metric)
- **Multi-channel notifications**:
  - Slack webhooks
  - Email (via SMTP)
- Persists alert history to avoid duplicate notifications

**4. Data Persistence**
- Saves alert state to JSON file (`alerts_state.json`)
- Logs all alerts to SQLite database (`alert_logs` table) with:
  - Timestamp, metric name, value, threshold
  - Which channels were notified
  - Success/failure status

**5. Configuration** (via environment variables)
- `ALERT_LOOKBACK`: Number of recent samples for baseline (default: 30)
- `ALERT_K`: Z-score threshold multiplier (default: 2.0)
- `ALERT_COOLDOWN_HOURS`: Hours between repeat alerts (default: 24)
- `SLACK_WEBHOOK_URL`, `ALERT_SMTP_*`: Notification settings
- `ALERT_DB_PATH`: Where to store alert logs

Looking at alerts_module.py, this is a simpler alternative health monitoring system for Garmin data. Here's what it does:

Core Functionality
1. Baseline Computation

Analyzes the last 30 days (configurable) of Garmin activity data
Computes rolling baselines for 3 metrics:
Gait: Stride length standard deviation
HR Drift: Average heart rate mean
Heat Sensitivity: Correlation coefficient between heart rate and temperature
2. Alert Detection

Compares computed baselines against fixed thresholds:
Gait variability > 0.15m (default)
HR drift baseline > 10 bpm (default)
Heat sensitivity correlation > 0.25 (default)
3. Notifications

Sends alerts via:
Slack: Using webhook URL
Email: Via SMTP (Gmail by default)
Only triggers when thresholds are exceeded
4. Configuration (environment variables)

DB_PATH: Path to garmin_activities.db
SLACK_WEBHOOK_URL: Slack integration
EMAIL_ENABLED, EMAIL_SMTP_*: Email settings
ALERT_THRESHOLD_*: Threshold values for each metric
LOOKBACK_DAYS: Rolling window size (default: 30)
Key Differences from alerts.py
This module is simpler than [alerts.py](c:\smakryko\MS-Buddy-Fitness-App_Garmin-MS-HelthDashBoard by ChatGPT\alerts.py):

❌ No z-score statistical analysis
❌ No cooldown mechanism (could spam alerts)
❌ No alert history/state persistence
❌ No database logging of alerts
❌ Doesn't read CSV files - queries database directly
It appears to be a lightweight, standalone alternative for basic threshold-based alerting without the sophisticated statistical analysis and state management of alerts.py.
